# CLAUDE.md

This is a public record of self-directed learning that uses only official, publicly available Anthropic / Claude training. It is not a curriculum, a certification, or career guidance.

## Scope rules

- Include only training that Anthropic itself publicly offers and that an individual can access without belonging to a partner organization.
- Do not invent curriculum, role requirements, capstones, portfolio requirements, interview advice, or time estimates unless the owner explicitly asks.
- Do not add unofficial courses or role-specific recommendations unless the owner explicitly expands the scope.
- Completion badges are not professional certification. Keep public completion badges clearly separate from credentials that require partner access or employer nomination.
- Keep listed course order as catalog order, not as an Anthropic-mandated sequence, unless Anthropic explicitly says otherwise.

## Sources and accuracy

- Use primary Anthropic sources for every claim about availability, duration, eligibility, or credentials. Check them before changing any such claim.
- Record the source URL and access date (YYYY-MM-DD) whenever catalog or credential information is updated.
- Mark uncertain information explicitly. Do not fill gaps from general AI-industry knowledge.

## Never commit

- API keys, tokens, or account details.
- Course content that sits behind a sign-in wall.
- Private notes the owner has not chosen to publish.

## Git workflow

- Do not use pull requests. Commit directly to the default branch, `main`.
- Make each change a focused commit. Do not rewrite personal notes without explicit instruction.
- Always push after committing. Never leave the local repo dirty: no uncommitted changes, untracked files, or unpushed commits at the end of a task.
- Clean up leftovers without asking: delete stray or session-created branches (local and remote), temporary files, and any other clutter once they are no longer needed.

## Repository conventions

- Versioned Markdown in this repo is the source of truth. GitHub Issues may track individual course tasks. A GitHub Project board, if used, is only a view.
- Keep this file small and readable. Put long procedures in ordinary Markdown or an on-demand skill.
